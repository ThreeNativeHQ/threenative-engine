**Status:** PARTIAL (0.3.6 is published and its clean room is green; 5 of the 31 reachable sandbox games run it, the rest are blocked on native-engine gaps)
**Priority:** P1 — the 0.3.6 release blockers are fixed and published (AC-1 to AC-5); what is left is AC-6 and AC-7: 26 sandbox games still fail their own `pnpm test` on the native engine default.
**Complexity:** 6 (MEDIUM); risk override: none. Touches 3-6 engine files (+1), crosses the npm and GitHub release boundary (+2), works with complex scene-transition state (+2), and talks to the registry (+1).

**Depends on:** PRD-624 (0.3.5 release, done apart from close-out). PRD-629 (release in one command) shortens Phase 3 but is not required.

## Solution

1. **Make the restart failure deterministic first.** A restart-loop scenario restarts the starter N
   times on a cold, freshly cooked project and asserts the world after each one. Run it on the
   native web engine with `--browser-recipe webgpu` and a named adapter. Find out whether the world
   is absent for a bounded number of frames (a held draw while the new chain compiles) or for
   good (a disposed chain, pass or target still bound). Fix the engine layer that owns the cause.
   The fix is never a longer wait in the scenario (playtest AGENTS: "Never fix a boot race by
   lengthening a wait").
2. **Fix the Android bundle** so that a module with a top-level await is never inlined into a
   non-async initializer, or so that the native bundle target keeps such modules at the top level.
   Then fix the iOS consumer fixture: write the two files it imports, or remove the imports.
3. **Ship 0.3.6 through the normal chain,** and run the CI clean room (`npm-release.yml`,
   `clean_room_only`) against the published cohort. Then move every sandbox game that depends on
   core onto 0.3.6 **from the registry** (the user-like install). Lane tarballs move only after
   their lane change is confirmed in 0.3.6. A lane change that is not in 0.3.6 keeps its tarball,
   with the reason recorded in that game's `FRICTION.md`.

## Blocked on

- **Native engine gaps (owner: engine runtime).** `StorageTexture` (5 games), a `metalness` and `roughness` scene-pass target (5 games, or port their forked `worldEnvironment.ts` to the starter's tier-gated version), `TN_TSL_WGSL_INCLUDES` (2), glTF `KHR_materials_emissive_strength`, texture `clone`, `modelWorldMatrix`. Each is its own change in `packages/` with a native proof, then the game moves. Unblocks AC-6 and AC-7 for those games. A game may instead keep `engine: "threejs"`, which is the legacy fallback the owner rejected on 2026-10-15, so this PRD does not use it.
- **Game-side fixes (owner: sandbox).** `cloth-catcher-v2`, `fox-native` and `ue-static-import` need their scenario or manifest repaired, and `networkErrorsOptOutReason` needs a true reason from whoever owns the game. The 6 unisolated games need one run each with the console and the playtest artifact read.
- **`fab-import-proof`, `fluid-lab`, `lumen-hall`, `wildwood`** have uncommitted work in the sandbox repository. They move once their owners commit or discard it.
- **`release:ship` stops on the iOS job.** `scripts/release-ship.ts` counts any failed tag-run job as a failed run (`TN_SHIP_TAG_RUN_FAILED`), so it stopped after the tag run although `finalize` passed. The publish was finished by hand with `pnpm release --yes --skip-gates`, which is the step `release:ship` runs. Teaching `release:ship` to ignore the non-gating iOS job is a follow-up for PRD-629.
- **`xvfb.spec.ts` flake.** `scripts/__tests__/xvfb.spec.ts:118` failed once on the `main` CI run (attempt 3) and passed on attempt 4: `xvfb.sh` waits 0.25 s for a compositor that the fake test one starts after 0.1 s.

## Decisions

- **AC-4 removed (R4), 2026-10-21.** The box asked for `clean-consumer-ios` green on a `release-proof` run. iOS is not a supported target (owner, 2026-09-23, recorded in `.github/workflows/native-release.yml` above `finalize`): its consumer proof stays as evidence and does not gate promotion. The job was `skipped` on the rehearsal runs 39500371302 and 39524553443 and `failed` on the tag run 39574813457, whose gating jobs and `finalize` passed. A box that cannot be ticked and does not gate the release is moot. The unproven iOS fix (the job copies `networking-game.ts` and `worker-proof.ts` beside `game.ts`) stays in the workflow as evidence-only.
