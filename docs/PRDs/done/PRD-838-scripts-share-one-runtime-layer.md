## Solution

`scripts/lib/{dev-server,exec,mcp-client,gh,args}.ts`, one implementation each. The strictest variant
wins: check the child's exit, throw on non-zero, retry `gh` once. Every local copy is deleted. The perf
verdict moves into `@threenative/playtest`, and `report.ts` imports it. Dead scripts are deleted, and
each orphan gate is wired into `pnpm budgets` or deleted.

## Decisions

- **`scripts/lib/args.ts` is dropped** (2026-11-07). The Solution and Phase 1's file list named it, and no caller needed it: each script's argument parsing is a handful of `process.argv` reads with its own usage text and its own exit code, and the five copies differ in every one of those. A shared parser would either take a spec per script (more code than it removes) or force one usage text on tools whose contracts differ. Revisit if a sixth copy appears that is actually the same shape.
- **The four "orphan gates" stay as they are** (2026-11-07): see Phase 2's box, which records why each is covered by the suite or is an evidence producer rather than a gate.
- **AC-1's visual gate is `pnpm visuals:baseline`, with `pnpm visuals` recorded as reached-but-human-gated** (2026-11-08). The box claims one visual gate still runs end to end. `pnpm visuals` ran every step this PRD's helpers own (structure, scaffold, build, the dev-server waits, capture of 16 kits, the parity bundle) and then stopped on a human-score precondition that has been stale since 2026-08-21. `pnpm visuals:baseline` runs the same capture path and needs no score file, so it carries the claim. `pnpm visuals` cannot exit 0 on any branch until the owner re-scores the kits. Two checks stand in the way. First, `TN_VISUAL_SCORE_TEMPLATES_MISMATCH` (10 kits missing, `defense` renamed). Second, `scripts/visual-gate.ts:344` fails any template below `VISUAL_SCORE_FLOOR = 4`, and the existing model scores already hold racing 2, and action-rpg, minimal, platformer and shooter at 3. So a green `pnpm visuals` measures template beauty, not whether the scripts run, and filling scores to pass it would inflate them. The owner holds that gap: re-score all kits, then decide whether the floor still applies.

## Execution Phases

#### Phase 1: Shared lib
**Status:** DONE
**Files:** new `scripts/lib/dev-server.ts`, `exec.ts`, `mcp-client.ts`, `gh.ts`, `args.ts`; the callers listed above.

- [x] One dev-server helper fails fast when the server process exits, and every caller uses it. `scripts/lib/dev-server.ts` exports `waitForServer({ url, child?, timeoutMs?, intervalMs?, label?, detail? })` and `DevServerError` with `TN_DEV_SERVER_EXITED` / `TN_DEV_SERVER_TIMEOUT`; it notices `exitCode` **and** `signalCode`, and appends the caller's corrective detail. Nine call sites now route through it (`env-cost-probe`, `visual-gate`, `verify-golden-path`, `profile-starter`, `profile-native-cpu`, `engine-load-test/browser` + `cli` + `skinned-crowd`, `unreal-look/capture-threenative` + `tier-live-step` + `capture-gi-threenative` + `gi-tier-cost`). Three of them had no exit check at all and would have spent their full timeout on a dead server (`env-cost-probe`, `engine-load-test/cli` and `skinned-crowd`); the two `waitForServer*` functions left in `scripts/run-networking-proof.mjs` wait on **game** state (players joining, a session ending), not on a dev server, and stay. proof: `npx vitest run scripts/__tests__/dev-server.spec.ts` → 4 passed (a real child that exits at once, a child that dies mid-wait, the deadline, and the corrective detail); `rg -n 'function waitFor(Server|Url|Port)' scripts --glob '!lib/**'` returns only those two game-state waits; `pnpm typecheck` → 0.
- [x] One `exec`, one MCP client and one `gh` wrapper, and the local copies are deleted. `scripts/lib/exec.ts` (`run`/`runAsync`, `ExecError` with the caller's code, capture-or-stream, kill deadline) replaced **eight** `run()` copies; `scripts/lib/gh.mjs` replaced **four** `gh` wrappers; `scripts/lib/mcp-client.ts` (`startMcpServer` → `request`/`notify`/`initialize`/`stderr`/`alive`/`close`, `McpError` with `TN_MCP_EXITED`/`TN_MCP_TIMEOUT`/`TN_MCP_REPLY`) replaced the four stdio handshakes in `capture-mcp-tools`, `capture-asset-mcp-tools`, `verify-golden-path` and `verify-forest-playtest`. `verify-registry-install.ts` composes request *lines* for a pipeline rather than talking to a server, so it has no client to share. `gh` is not a single copy yet either: `ci-change-scope.mjs`, `release-candidate-gate.ts`, `ci-attempt-receipts.mjs`, `release-ship.ts` and `release-native-local.ts` keep their own, so "every local copy is deleted" is true of the four this box converted and not of those five. Two of the old copies were genuinely wrong (`verify-forest-playtest` resolved a reply on the *substring* `"id":2`, so a chunk boundary decided whether it answered, and its `terrain_generate` had no deadline while a forest cook takes longer than a request), and two defects were mine, caught before the review gate: the first conversion passed a **label** where the runner reads a working directory, and the golden-path mutation control excluded the `template-assets/patches` directory that carries the manifest `prepack` reads. The client also listens on the server's stdin, because an EPIPE there is an uncaught stream error; its spec closes the server's fd 0 from an ESM `closeSync` and asserts `TN_MCP_EXITED … closed its input`, which goes red (`Error: write EPIPE`) the moment the listener is removed. Closing the trap that let a label be read as a working directory, `run`/`runAsync` now refuse a `cwd` that does not exist (`TN_EXEC_BAD_CWD`) and `packReleaseSet` takes its runner as a seam, with a spec that asserts every pack call carries the repository as its cwd. The client also now sends `notifications/initialized` inside `initialize`, so a caller cannot forget it. proof: `npx vitest run scripts/__tests__/exec.spec.ts scripts/__tests__/gh.spec.ts scripts/__tests__/mcp-client.spec.ts scripts/__tests__/dev-server.spec.ts scripts/__tests__/verify-golden-path.spec.ts scripts/__tests__/verify-forest-playtest.spec.ts scripts/__tests__/capture-asset-mcp-tools.spec.ts scripts/__tests__/release.spec.ts scripts/__tests__/prepare-release.spec.ts scripts/__tests__/make-sandbox.spec.ts scripts/__tests__/verify-template-playtests.spec.ts` → 146 passed; `pnpm typecheck` → 0.
