# PRD-609 — A GPU burst starts where and when it is asked, and live particles stay put

**Status:** DONE 2026-10-12 — AC-1 to AC-4 and all phase boxes verified; visual judge NEUTRAL (look unchanged)
**Priority:** P1 — core correctness bug in `GPUParticles3D`: AC-1 to AC-3 are open, a burst begins with its particles at random points of their lives, and a second hit moves the first hit's live particles. Every game with hit effects sees it.
**Complexity:** 6 (MEDIUM) — 6–10 files (`particles.ts`, its spec, a conformance scene and registry row, the gallery probe, the action-rpg template) (+2), new public method and option set (+2), ring state that carries across frames (+2); risk override: none
**Owner:** unassigned
**Depends on:** None. Coordinate with [PRD-569](PRD-569-gpu-particle-emitters-cull-and-yield-to-the-frame-budget.md): its `"clear"` cull reaction calls `restart()`, which this PRD defines for spawn-driven emitters. Respects [PRD-316](../Unreal/vfx/PRD-316-forty-six-vfx-are-generated-render-source-not-an-engine-inside-the-engine.md) (§3): the new surface moves no appearance decision into core.

## Context

`GPUParticles3D` (`packages/core/src/particles.ts:30`) owns two storage buffers, `positions` and `velocities` (`particles.ts:7-10`, `particles.ts:51-54`). The game supplies a `start` kernel and a `process` kernel (`particles.ts:12-17`). `restart()` only reruns the `start` kernel (`particles.ts:81-86`). The class has no spawn request, no birth time and no notion of a free slot. Every effect that ships is therefore a closed-form function of time.

The action-rpg template shows the cost. Its `phase()` is `fract(time / lifetime + hash)` (`packages/create-threenative/templates/action-rpg/src/render/vfx.ts:68-73`). Its `process` kernel writes each position as a pure function of that phase (`vfx.ts:167-181`). So a "burst" is a loop that runs forever at random offsets, and the `start` kernel's writes are overwritten on the first `process` dispatch. The scene's `burst()` helper hides the loop (`packages/create-threenative/templates/action-rpg/src/scenes/Play.ts:219-231`). It moves the emitter to the hit point (`Play.ts:224`), shows it (`Play.ts:225`), calls `restart()` (`Play.ts:226`), and schedules a hide 0.45 s later (`Play.ts:227-229`). The attack, hit and surge paths all call it (`Play.ts:391, 403, 423`).

Reading the code predicts three defects. Phase 1 measures them before any engine work:

1. A burst does not start at its birth. The first visible frame shows particles at random ages, so the effect begins half spent.
2. The sprite draws buffer positions in the emitter's own space. Moving the emitter at the second hit moves every live particle of the first hit to the new place.
3. The first hit's hide timer is never cancelled. It hides the second burst early.

A game cannot fix this in `src/render/`. The fix needs a per-particle birth time, an allocator for free slots and a spawn request that reaches the kernel. Those are the plumbing every burst repeats. They decide no color, shape, speed or lifetime, so the two questions in the root `AGENTS.md` put the mechanism in core and the appearance in the game. `GPUParticles3D` stays the shape: the engine owns the slots, the game owns the kernels.

### What Unreal does (UE 5.8.3, read 2026-10-12; clean-room summary, no code copied)

- **A spawn is a request, not a restart.** Each frame the CPU builds a short list of spawn infos. Each info holds a count, a start offset inside the frame, an interval between particles and a group. The list travels to the GPU context with the emitter's maximum particle count (`UE 5.8.3: Engine/Plugins/FX/Niagara/Source/Niagara/Classes/NiagaraComputeExecutionContext.h:27-48`, `Private/NiagaraEmitterInstanceImpl.cpp:1417-1424`). An emitter holds at most 8 infos per frame (`Public/NiagaraCommon.h:75`).
- **The sub-frame offset spreads one frame's births.** A spawn info carries the time of its first particle and the gap between particles (`Public/NiagaraTypes.h:346-351`). An emitter chooses whether new particles run the spawn script only or spawn plus update with interpolation (`Classes/NiagaraEmitter.h:318-320`).
- **The clamp is late and the cap is loud.** The CPU cannot know the live count, so it does not clamp. The GPU side clamps the new total to the buffer size (`Private/NiagaraEmitterInstanceImpl.cpp:1435-1438`, `Private/NiagaraGpuComputeDispatch.cpp:880-882`). A per-frame spawn cap defaults to 2,000,000 and an emitter may override it. Passing the cap logs a warning and stops adding infos (`NiagaraEmitterInstanceImpl.cpp:75-81, 1441-1451`, `Classes/NiagaraEmitter.h:372-374`).
- **World space is the default.** Particles are relative to the emitter origin only when the emitter asks (`Classes/NiagaraEmitter.h:305-308`, `bLocalSpace = false`). Godot uses the same default through `local_coords`.
- **Stable IDs are opt in.** Alive particles are packed tightly, so an index changes between frames. A stable ID costs memory and time, and an emitter turns it on only when something outside tracks a particle (`Classes/NiagaraEmitter.h:359-361`, `Classes/NiagaraDataSet.h:305-316`, a free-ID table). This PRD takes the cheaper reading: slots are ring-allocated and never tracked.
- **The cheap tier is closed form.** Stateless emitters rebuild their particles from a seed, the emitter age, the time step and the spawn list (`Private/Stateless/NiagaraStatelessComputeManager.cpp:80, 94`). ThreeNative's shipped effects have the first three inputs and lack the spawn list. This PRD adds the spawn list.
- **Event spawns still count on the CPU.** Even for a GPU emitter, the event spawn count comes from the source emitter's event data on the CPU, and only the total reaches the GPU context (`NiagaraEmitterInstanceImpl.cpp:1295-1318, 1422`). So Unreal has no readback-free on-death spawn for this path. This PRD does not file one. See Decisions.

## Solution

Core owns the ring of slots, the birth stamp and the spawn uniforms. The game owns every kernel.

1. **A spawn kernel, like `start`.** `IGPUParticles3DOptions` gains an optional `spawn: (buffers, request) => ComputeNode`. The `request` holds engine-owned uniform nodes: `first` (the first ring slot), `count`, `origin` (a world position), `direction`, `seed` and `time`. The kernel dispatches over `amount` threads. A thread with `instanceIndex >= count` returns at once. The slot is `(first + instanceIndex) % amount`. This costs `amount` threads per emit, which is small at the counts templates use. ponytail: upgrade to an indirect dispatch of exactly `count` threads only if a game's `amount` passes about 100,000 and the emit cost shows in `compute-timing`.
2. **A birth buffer and a clock, written by the engine.** `buffers.births` is a float buffer that holds the emitter-clock second of each slot's last spawn. Slots start "dead" (a birth far in the past). The engine writes births in its own tiny dispatch, so a game kernel cannot forget to. `process(buffers, runtime)` receives `runtime.time` and `runtime.delta` as TSL nodes. The game computes `age = time - births[i]` and decides when a slot is dead. The existing one-parameter `process` keeps working.
3. **`emitParticle(request)`**, borrowing Godot's `emit_particle` name. `request` is `{ count?, origin?, direction?, seed? }`. The engine reserves `count` ring slots from a CPU cursor, writes the uniforms, and dispatches the engine birth stamp and the game's `spawn` kernel. There is no readback. Calls in one frame stack, and each call gets its own slots.
4. **Bounded, and honest about it.** A request over `amount` clamps to `amount`. Requests in one frame clamp to a `maxSpawnPerFrame` option that defaults to `amount`. Each clamp adds to `stats.clamped` and warns once per emitter. The ring recycles the oldest slots. With the optional `lifetime` option (a game-owned maximum, in seconds) the engine counts `stats.recycledLive` from a small CPU log of recent requests. Without `lifetime`, `recycledLive` is `undefined`, never `0`.
5. **World space by default.** When `spawn` is given, `localCoords` defaults to `false`. The engine holds the emitter's world matrix at identity, so buffer positions are world positions and a moving parent moves nothing. `localCoords: true` is the named override. Emitters without `spawn` keep `localCoords: true`, so every shipped effect is unchanged.
6. **`restart()` clears a spawn-driven emitter.** It resets every birth to dead and the cursor to 0. A closed-form emitter keeps today's behavior.

Consumer flow: a hit in the action-rpg scene calls `hitVfx.emitParticle({ count: 220, origin: hit.position })`. Core reserves slots, stamps births and dispatches the template's `spawn` kernel from `src/render/vfx.ts`. The template's `process` kernel integrates by age. The emitter stays visible, so the helper loses `position.copy`, the show/hide pair and the timer.

Reused systems: `ComputeDrivenRegistry` for attach, warm-up and release (`packages/core/src/compute-driven.ts`), `GPUReadback` for the probe (`packages/core/src/gpu-readback.ts`), the `vfx-compute` conformance row as the pattern for the native row (`packages/runtime-native/conformance/registry.json`).

## Decisions

- 2026-10-12 (PRD shape, R5): the PRD had 12 boxes against a cap of about 8. The Phase 2 probe-arm box and desktop-parity box repeated AC-1/AC-2 and AC-4, so they were dropped in favour of the ACs. The two spec boxes became one, and the template-docs and manifest boxes became one. No criterion was weakened. Priority raised from P2 to P1 on the owner's call: core correctness bug every game with hit effects sees.

- 2026-10-12 (Unreal source review): no readback-free on-death spawn. Unreal counts event spawns on the CPU even for a GPU emitter (`NiagaraEmitterInstanceImpl.cpp:1295-1318`). A ThreeNative version would need atomic appends and an indirect dispatch. No effect here has a measured need. File it only with a real sub-emitter consumer.
- 2026-10-12 (phase 1 gate): CONTINUE. The restart-based burst shows all three predicted defects: mean age fraction 0.476 at the first visible frame (gate: above 0.10), 6.15 m largest one-frame particle move at the second burst (gate: above 0.5 m), and the second burst hidden after 9 of 27 frames. The probe runs wall-clock (`--live-clock`) because the scenario's ticks outrun rendered frames and starve the readback, and on the Debian laptop's real display because the desktop's private Xvfb serves SwiftShader.
- 2026-10-12: no sub-frame birth spread. Bursts are instants. Add the spread (Unreal's start offset and interval) with the first rate emitter that shows clumping.
- 2026-10-12: closed-form emitters stay valid and stay the cheap tier. Rain, snow and runner dust are continuous and look the same at any time, so they need no spawn list.
- 2026-10-12 (visual judge): NEUTRAL, twice. The Phase 3 text read "NEUTRAL or REGRESSION means fix", but the template look values were meant to stay unchanged, so NEUTRAL is the passing verdict and only REGRESSION fails. Two fresh read-only Sonnet judges compared the old and new code on the Debian laptop's Intel gen-12lp at two runs per arm (hit sparks, attack arc, surge): same places, colours, sizes and density within run noise; no stray cluster, stuck burst, blank frame or wrong scale. Frames: `~/Downloads/prd-609-vfx/` and the PR.
- 2026-10-12 (open observation, not a criterion): on the desktop's RTX 2080 lane, which runs through the per-process ICD shim for a driver mismatch (`VK_ERROR_DEVICE_LOST`), the new template lost the GPU device in 3 of 8 scenarios of the full sweep and in all three plain runs of the attack-then-second-strike capture (`attack2` and the attack-then-surge capture twice). Three sweep scenarios (`survives`, `progress`, `win`) passed when rerun alone, and one run with extra console logging passed. Emitting no hit bursts, or one per strike, passed; the strike can emit two hit bursts in one frame. The old restart-based code never lost the device in the same scenarios. Three's `compute()` submits each call on its own, so same-frame emits stay in order. The same scenario on Intel and the gallery overflow arm (three requests per frame) pass, and the single-GPU-lane cause is unproven. Next step if it matters: reproduce on a second NVIDIA host without the shim.
