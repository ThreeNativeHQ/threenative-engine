# PRD-631 — An Unreal reference scene measures the default look

**Status:** IN PROGRESS
**Priority:** P1 — no box is ticked: no reference frame exists, so every "Unreal look" PRD in [`../README.md`](../README.md) tunes against memory instead of a measurement.
**Complexity:** 6 (MEDIUM) — new tool folder and two capture scripts (+2), an external renderer driven headless (+2), cross-engine coordinate and unit mapping (+1), a comparison report that later PRDs gate on (+1); risk override: none
**Owner:** João
**Depends on:** None. Every layer PRD in [`../look/`](./) waits on Phase 3 of this PRD.

## Context

The Unreal PRDs in this folder copy mechanisms from the Unreal 5.8.3 source. None of them can say
whether ThreeNative now *looks like* Unreal, because nothing renders the same scene in both engines.
The template look today was tuned by eye against photographs and earlier frames:

- The starter `high` tier runs three.js ACES at a hand-set exposure of 0.62, bloom 0.22 with
  threshold 1, vignette 0.22, GTAO, SMAA, a photographed sky as the environment, and height fog
  (`packages/create-threenative/templates/starter/src/render/quality.ts`).
- SSGI, SSR, TAA, auto exposure, volumetric mist and the LUT `Atmosphere` are shipped as mechanisms
  and are off in every template (scout of 2026-10-19, recorded under `## Decisions`).

A fresh Unreal 5 project turns on, with no tuning: the Sky Atmosphere with a real-time Sky Light
capture, Exponential Height Fog, Lumen global illumination and reflections, virtual shadow maps,
histogram auto exposure, the filmic tonemapper, bloom and TSR. That combination is what people mean
by "the Unreal look". This PRD builds the instrument that measures the distance to it, one layer at
a time.

### Why one layer at a time

A frame that differs in tone, sky, fog, shadow and bounce at once cannot say which system is wrong.
Unreal can switch each system off with a console variable. So the capture matrix is cumulative:
each layer adds one system on top of the layer below it, in both engines. A layer PRD tunes only
its own row, and the rows below it must still match.

| Layer | Adds | Unreal switches (the rest of the ladder stays off) |
| --- | --- | --- |
| L0 | Geometry and camera only: unlit base colour | `ShowFlag.Lighting 0`, all post off |
| L1 | Sun and sky light, fixed exposure, tonemapper | `r.DynamicGlobalIlluminationMethod 0`, `r.ReflectionMethod 0`, `r.DefaultFeature.AutoExposure 0`, `r.BloomQuality 0`, `r.AmbientOcclusionLevels 0`, `r.Fog 0`, `r.VolumetricCloud 0`, `r.Shadow.Virtual.Enable 0`, shadows off |
| L2 | Sky atmosphere, sky light real-time capture | L1 with the atmosphere on |
| L3 | Height fog, volumetric fog, aerial perspective | `r.Fog 1`, `r.VolumetricFog 1` |
| L4 | Volumetric clouds | `r.VolumetricCloud 1` |
| L5 | Sun shadows (virtual shadow maps, soft by source angle) | `r.Shadow.Virtual.Enable 1` |
| L6 | Ambient occlusion | `r.AmbientOcclusionLevels -1` |
| L7 | Global illumination | `r.DynamicGlobalIlluminationMethod 1` |
| L8 | Reflections | `r.ReflectionMethod 1` |
| L9 | Bloom, auto exposure, anti-aliasing: the full default | every switch at its project default |

The console-variable names above come from the 2026-10-19 source scout. Phase 1 confirms each one on
the installed 5.8.3 binary before it is used, and replaces any name that does not resolve.

### The scene

One GLB, loaded by both engines, generated by a script so either side can be rebuilt:

- A 40 m grey floor (base colour 0.18 linear, roughness 0.8).
- Five spheres in a row: rough dielectric, smooth dielectric, rough metal, chrome, emissive.
- Three coloured boxes (red, green, white) for colour bleed.
- A 6 m room with one open wall, for bounce light and interior exposure.
- A wall that stands between the camera and a low sun, for the backlit case.
- One 1.8 m capsule, for scale and for shadow contact.

Three sun elevations (60°, 15°, 4°) and four camera poses (exterior wide, sphere row, room
interior, backlit wall) give 12 frames per layer.

### Coordinate and unit traps

The two engines disagree on conventions. Phase 2 has to handle these before any lighting comparison
means anything:

- Unreal is Z-up and left-handed, in centimetres. three.js is Y-up and right-handed, in metres.
- An Unreal camera FOV is horizontal. A three.js `PerspectiveCamera.fov` is vertical.
- Unreal sun intensity is in lux. Its default exposure is set in EV100. ThreeNative has no
  physical light units today.
- Unreal renders the base colour in linear space from sRGB textures, as three.js does. The L0 frame
  proves it.

## Solution

1. **Unreal side** (`tools/unreal-reference/`, run with `UE_ROOT` set to an installed Unreal
   5.8.3):
   - A `.uproject` and a `Config/DefaultEngine.ini`. We write these files ourselves. They set the
     same renderer settings as a fresh Blank project, and nothing more.
   - `build_level.py`, run by `UnrealEditor-Cmd -ExecutePythonScript`, opens a new level from the
     editor's own default level template, so it gets the lighting actors with the values a user
     gets: Sky Atmosphere, Volumetric Cloud, Exponential Height Fog, Sky Light and the atmosphere sun
     Directional Light. It deletes the template's floor, imports the GLB, and adds one unbounded
     post-process volume with no overrides. It writes every lighting actor's values (sun lux and
     source angle, sky light capture mode, fog density, cloud layer) to `template-actors.json`.
     The source scout could not find these values, because they live in the binary template map
     and not in constructors. Every layer PRD reads its starting values from that file.
   - It renders every (layer, sun, pose) cell through Movie Render Queue, with warm-up frames so
     Lumen, the virtual shadow maps and TSR settle. Each cell produces a display-referred PNG and a
     scene-linear EXR.
   - **How an agent controls Unreal.** The work uses two channels, and neither one is a
     third-party server:
     - *Batch capture* runs `UnrealEditor-Cmd -ExecutePythonScript` headless. It is
       deterministic, scriptable and needs no running editor. Only this channel produces cells.
     - *Interactive inspection* uses Epic's own experimental **Unreal MCP** plugin
       (`Engine/Plugins/Experimental/ModelContextProtocol`, in the 5.8.3 install). It serves
       streamable HTTP at `http://localhost:8000/mcp` (`-ModelContextProtocolPort=` overrides the
       port), with the `EditorToolset` and `ConfigSettingsToolset` from
       `Engine/Plugins/Experimental/Toolsets/`.
     - The MCP tools include `CaptureViewport`, `SetCameraTransform`, `GetVisibleActors`,
       `SelectActors`, `SearchCVars`, `GetLogEntries` and `StartPIE`. An agent can open the level,
       read an actor's values, frame a pose and look at it while it tunes a layer. Connect with
       `claude mcp add --transport http unreal http://localhost:8000/mcp`.
     - The MCP has no tool that runs Python or console commands. So it never replaces the batch
       script, and a value read through it is evidence only after the batch run reproduces it.
     - Community servers were checked on 2026-10-19: sam-david, groscy, runreal and
       FFZackFair92 `unreal-mcp`, and `uemcp`. Each is a wrapper over the same built-in Python
       Remote Execution or Remote Control plugins. Adopt one only if a needed tool is missing from
       Epic's server and from the batch script, and record that decision here.
2. **ThreeNative side**: a script scaffolds the `starter` template into a temporary folder and
   loads the same GLB with the same poses. It captures the same cells headed on WebGPU and checks
   `adapter.info`. It edits only that copy's scene setup. The look stays in the scaffolded
   `src/render/`, so tuning a layer means editing the template source. It never means editing
   the harness.
3. **Comparison**: `compare.ts` pairs the cells. Per frame and per region mask (sky, lit floor,
   shadowed floor, each sphere, room interior), it reports:
   - display luminance quantiles (p1, p50, p99), using `packages/playtest/src/tone.ts`
   - scene-linear luminance quantiles in EV
   - the median colour difference (CIEDE2000)
   - a side-by-side contact sheet

   It fails closed on a missing cell, a size mismatch or an empty region mask.
4. **Reference statistics stay tracked, images do not.** Captures are large and anyone with Unreal
   can regenerate them. `tools/unreal-reference/reference-stats.json` holds the Unreal numbers per
   cell, so `compare.ts` runs on a machine without Unreal. Only that file and the sheet of the
   Phase 3 baseline are committed.

### Licence

This PRD commits no Unreal code, shader, asset or `.uasset` file. The level is built at run time
from engine default actors and our own GLB, and the config files are written by us. The frames are
renders of our own scene. Read [`../README.md`](../README.md) "The licence rule" before you touch
the Unreal tree.

### The default-on contract that the layer PRDs inherit

A layer PRD may turn its system on by default in the templates only when all of these hold:

1. Its layer row and every row below it are inside the match thresholds that Phase 3 measures.
2. A visual judge subagent returns IMPROVEMENT against the current template default, on the same
   cells, with the Unreal frame as the stated target (root `AGENTS.md`, "Visual judge subagent").
3. The `high` tier frame budget still holds on the RTX 2080 browser lane.
4. The `low` tier has a named fallback that still draws a picture.
5. The native desktop host renders it (a conformance case or a `--target desktop` playtest).
6. Each affected template's `AGENTS.md` names the default and its override. The root `AGENTS.md`
   says a convention missing from the templates' `AGENTS.md` does not exist.

The layer PRDs change `packages/create-threenative/templates/*`, so every new project scaffolds
with the Unreal look as each layer passes. A template whose art direction the reference does not
suit (for example platformer's gradient sky) keeps its own value for that layer, and the layer PRD
records it by name. Projects scaffolded before a layer lands keep their own `src/render/` source,
because generated source belongs to the game.

- 2026-10-20 (L0 silhouette measure): Unreal draws its ID frame aliased and ThreeNative draws it multisampled, so a blended edge pixel carries no region on one side only. `silhouetteIou` leaves a pixel with no region in either frame out of both. A pixel that the two frames give to different regions still counts, so a shift of more than one pixel (the width of a blended edge) still lowers the IoU. The alternative, turning multisampling off for the ID page, needs a per-page config that the capture harness does not have.
